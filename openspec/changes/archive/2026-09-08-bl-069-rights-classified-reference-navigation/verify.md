## Material Reproduction Records

- The first dependency audit found `pdfjs-dist@5.6.205` inside `GHSA-hq66-cqwq-w95j`. Reproduction: install that exact version and run `npm audit`. Resolution: exact-pin Node-20-compatible `5.5.207`; the PDF.js advisory is no longer reported.
- Updating the package while a Vite optimizer cache was live could pair an old optimized API module with the new worker. Reproduction: change the package version without refreshing the dev optimizer, then open a PDF and observe an API/worker version-mismatch fallback. Resolution: both API and worker are emitted with `?url` from the same installed package, and the API asset is dynamically imported on viewer activation.
- The repository-wide four-project run can time out unrelated browser flows under sustained parallel PDF/browser load. The proof file now runs serially within each browser project; every timeout from the recorded full run passed when immediately rerun in its owning browser. Keep the nonzero comprehensive result visible until the repository-level concurrency policy is revisited.
- Live Storybook previously served the adopted PDF and PDF.js support assets at root-relative URLs while SvelteKit's `asset(...)` generated `/ez-chars/...` requests, so the story fell into its browser fallback even though the application worked. Reproduction: start the old `npm run storybook` and request `/ez-chars/docs/ext/5e2014/SRD_CC_v5.1.pdf` (404) versus `/docs/ext/5e2014/SRD_CC_v5.1.pdf` (200). Resolution: mark live and static Storybook builds so SvelteKit uses the root asset base and the shared Vite plugins serve/copy the same allowed resources without publishing `docs/ext/local-only`.
- Storybook's SvelteKit `MockProvider` prevented every story-preview anchor's default navigation, including anchors with `target="_blank"`, while its mocked shallow-navigation API emitted an action without changing the `$app/state` page observed by the production controller. Reproduction: activate any mixed-source external anchor or `Open in app` in the unconfigured story and observe no popup or viewer state change. Resolution: the unique mixed-source sandbox declares narrow external/local-document popup callbacks and owns a proof-only in-app viewer step; application tests continue to exercise the production history-aware controller.
- The first stale-safe Storybook return attempted to focus the trigger element that existed before the mixed-state list was temporarily unmounted. Reproduction: open the stale self-hosted source in-app, return to source states, and inspect `document.activeElement`. Resolution: remember the logical included/stale invoker and focus its newly rendered bound element after the list returns; the repeated live exercise confirms restoration.
- The first cross-browser collapse test exposed a three-column auto-placement error: removing the hidden resize divider left the PDF document in the zero-width divider column, reducing it to 34 pixels in Chromium, Firefox, and WebKit. Reproduction: minimize document navigation in the initial implementation. Resolution: the minimized state now declares an explicit two-column grid; the complete 20-check focused matrix and 108-case repository matrix pass afterward.
- The first WebKit resize run cancelled page rendering while text extraction was still pending, allowing `RenderingCancelledException` to surface before the final combined await attached.
